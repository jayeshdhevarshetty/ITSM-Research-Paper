# IT Service Management Research Paper

IT problems do not always start as big system failures. Sometimes, a small alert keeps coming back, takes up an engineer's time, and slowly becomes a bigger business problem. This research paper shows how IT teams can stop that cycle instead of only fixing the same issue again and again.

The project connects three parts of IT work that are usually handled separately: restoring service during an incident, finding the real cause of a repeated problem, and making a safe change to fix it for good. It uses a real production-support example where a better process reduced repeated incidents by about 70% across similar applications.

This is more than a class paper. It shows how I think about real IT operations: stay calm when systems fail, use evidence such as logs and incident history, communicate clearly, and turn repeated issues into lasting improvements.

The full paper explains how these three important IT processes work together:

- **Incident Management**: fixing an IT issue as quickly as possible.
- **Problem Management**: finding the real reason an issue keeps happening.
- **Change Management**: making a system change safely, without causing new problems.

## What this paper is about

Modern businesses depend on IT systems every day. When an application, server, or database fails, it can slow down work and affect customers. This paper looks at how IT teams can handle these issues in a better way.

Instead of only fixing the same issue again and again, IT teams can:

1. Restore the service quickly.
2. Find the root cause of repeated issues.
3. Make a safe, long-term fix.
4. Monitor the system to make sure the problem does not come back.

The paper also includes a real production-support example. In that case, a monitoring alert was creating repeated false incidents. By checking logs, finding the timing issue, and making a controlled change, the team reduced recurring incidents by about 70% across similar applications.

## Why this matters

Good IT service management helps companies:

- Reduce system downtime.
- Solve important issues faster.
- Avoid repeating the same work.
- Improve communication between teams.
- Make changes with less risk.
